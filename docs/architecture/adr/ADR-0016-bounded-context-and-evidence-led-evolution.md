# 有界上下文与证据驱动的 Agent 演进

## 背景

长时间的 Agent Run 会把模型请求中的历史工具结果、会话记忆和委派结果持续累积。
Provider 的输入缓存可以降低重复输入的计费或传输成本，但不会让上下文窗口无限增大，
也不会保证模型延迟、工具结果大小和运行时预算稳定。与此同时，系统性演进需要复用
已有公开调研证据，不能每轮从零开始检索并把结论留在瞬时对话里。

## 决策

1. Runtime 在每次模型调用前使用字符级防线限制上下文：单个工具结果有界，旧会话记忆和
   工具轮次可压缩，系统合同和当前任务固定保留；assistant 工具调用与对应 tool result
   作为完整轮次一起保留或丢弃。
2. 上下文压缩通过公共 `agent.progress` 事件报告原始/保留消息数和字符数；事件只包含
   有界、非敏感的度量，不持久化原始凭据或隐藏推理。
3. 委派 Agent 的最终结果和普通工具结果使用同一有界序列化路径，避免子 Agent 把大文本
   重新注入父 Agent 上下文。
4. Token cache 命中是 `TokenUsage` 的输入令牌元数据，不改变 UAI Forge 的总令牌账本、
   步数、工具调用或时间预算语义。
5. 公开研究证据以 `docs/research/` 下的 Markdown 研究笔记和索引持久化。后续 Run
   先读取索引和相关笔记，只补充新的来源、问题或结论；每项结论必须连接到 UAI Forge
   自有规范、实现或测试，不把第三方类型引入核心契约。

## 后果

- 长 Run 的输入增长和单次工具结果不会无界放大；模型仍可通过更窄的 workspace/web
  请求取得被截断的部分。
- 压缩会丢弃旧的瞬时上下文，因此 Agent 必须把重要结论写入工作区文档/checkpoint，
  不能依赖对话历史作为唯一事实源。
- 缓存命中仍然可观测，但不能作为放宽上下文或预算上限的理由。
- 研究笔记成为可审查、可复用的仓库资产；没有来源、取舍和 traceability 的研究不算
  已完成的演进证据。

## 边界

该 ADR 不宣称实现跨 Run checkpoint、分布式恢复、全局循环控制器或 Provider 特定的
缓存语义；这些能力仍需独立的规范、实现和故障测试。
